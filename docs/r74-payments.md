# r74 — исправления вкладки «Оплаты»

## Что меняется
1. **Абонементы в журнале по цене урока.** package_consumption и package_return несут сумму: purchase_amount / total_units, последняя единица забирает остаток. Баланс = платежи + корректировки − начисления − возвраты − стоимость списанных занятий. Сторно списаний учитывает сумму. Ручная корректировка единиц (adjust_package) остаётся неденежной.
2. **Долг и аванс из журнала**, по каждому ученику. Сумма по урокам осталась детализацией: lessons_due_amount и unallocated_payments_amount.
3. **Абонемент с другой длительностью.** Если длительность урока не совпадает с длительностью оплаченного абонемента, автозакрытие ставит «Требует решения» вместо молчаливого денежного начисления. Явное «списать из абонемента» списывает урок всегда.
4. **Сторно начисления** снимает привязки оплат: деньги уходят в аванс.
5. **audit_payment_integrity** (только чтение) проверяет, что у каждой оплаты ровно одна операция, что paid = Σ привязок, что нет урока одновременно с начислением и списанием абонемента, и сколько нулевых операций абонемента ждут backfill.
6. **Плановый доход** без бесплатных, пробных, «не начисляется» и отменённых записей. Абонементные уроки идут по цене урока в абонементе, перенесённые (moved) уроки учитываются.
7. **Часовой пояс учителя** применяется к месяцу в dashboard, к дате оплаты без времени (сохраняется как 12:00 по местному времени), к transactions from/to (to не включается) и к недельному графику (billing/weekSeries.js).
8. «Начислено» — по дате урока и с учётом абонементов (month_charged_money + month_charged_packages). «Проведённые» — по дате урока. Чтение счёта и абонемента больше не пишет в БД.

## Данные
`python manage.py backfill_package_ledger --dry-run --allocate-payments --report-json /root/r74-dryrun.json`
- Повторный запуск ничего не меняет.
- Ручные кейсы исключены по умолчанию: `--exclude 2:6,2:16,2:53,2:84,50:22`.
- Старый код суммы package_consumption не учитывает, поэтому откат только кода безопасен.
